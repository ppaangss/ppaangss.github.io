title: "TCP 3-way 핸드셰이크, 왜 세 번인가"

---

TCP 연결은 항상 세 번의 패킷 교환으로 시작한다. 두 번이면 안 되는 걸까? 결론부터 말하면, 양쪽 모두가 "내 시퀀스 번호가 상대에게 전달됐다"는 확신을 가지려면 최소 세 번이 필요하다.

## 각 단계에서 일어나는 일

클라이언트가 SYN을 보내고, 서버가 SYN-ACK으로 응답하고, 클라이언트가 마지막 ACK을 보내면 연결이 성립된다. 각 패킷에는 무작위로 생성된 초기 시퀀스 번호(ISN)가 실려 있다.

```
Client → Server   SYN      (seq=x)
Server → Client   SYN-ACK  (seq=y, ack=x+1)
Client → Server   ACK      (ack=y+1)
```

마지막 ACK이 없다면 서버는 자신이 보낸 SYN-ACK이 도착했는지 알 수 없다. 오래된 중복 SYN으로 유령 연결이 만들어지는 것을 막는 장치이기도 하다.

## 두 번으로는 안 되는 이유

연결은 양방향이다. 각 방향마다 "보내는 쪽의 시퀀스 번호를 받는 쪽이 확인"해야 하므로, 확인이 두 번 필요하다. 서버의 SYN과 클라이언트에 대한 ACK을 하나의 패킷(SYN-ACK)으로 합칠 수 있기 때문에 총 세 번이 최소가 된다.

- 1회차: 클라이언트 → 서버, 클라이언트의 시퀀스 전달
- 2회차: 서버 → 클라이언트, 서버의 시퀀스 전달 + 클라이언트 시퀀스 확인
- 3회차: 클라이언트 → 서버, 서버 시퀀스 확인

> 핸드셰이크는 "연결"이라는 상태를 만드는 게 아니라, 양쪽의 시작 번호에 대한 합의를 만드는 절차다.
