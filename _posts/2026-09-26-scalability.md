## 확장성이란 무엇인가

확장성은 "빠르다"가 아니다. **부하가 늘었을 때, 자원을 더 투입하면 그에 비례해 처리 능력이 늘어나는 성질**이다.

- **성능(Performance)**: 사용자 1명일 때 응답이 얼마나 빠른가
- **확장성(Scalability)**: 사용자가 10배가 됐을 때도 그 속도를 유지할 수 있는가

사용자 100명일 때 10ms로 응답하던 서버가 10만 명이 되자 10초가 걸린다면, 성능은 좋았지만 확장성이 없었던 것.

## 수직 확장 (Scale-up): 더 좋은 기계

서버 한 대를 더 강한 놈으로 교체. CPU 8코어 → 64코어, RAM 16GB → 512GB.

### 장점 

압도적으로 단순하다. 코드 한 줄 안 바꿔도 되고, 분산의 어려움이 아예 발생하지 않는다. 데이터가 한 곳에 있으니 트랜잭션도 조인도 그냥 된다.

### 한계 

1. **천장이 있다**: 세상에서 제일 비싼 서버보다 더 좋은 서버는 살 수 없다.
2. **가격이 선형이 아니다**: 2배 성능의 머신은 4배, 10배 비싸다. 상위 스펙으로 갈수록 가성비가 급격히 나빠진다.
3. **단일 장애점(SPOF)**: 그 한 대가 죽으면 전부 죽는다. 좋은 기계가 확장성은 사줘도 가용성은 못 사준다.

## 수평 확장 (Scale-out): 더 많은 기계

평범한 서버를 여러 대 놓고 부하를 나눈다.

### 장점 

이론상 천장이 없다. 값싼 범용 하드웨어라 비용이 선형에 가깝고, 한 대가 죽어도 나머지가 받아주니 **가용성이 따라온다**. 현대 대규모 시스템이 전부 이쪽인 이유.

### 대가 

로드 밸런서가 필요해지고, 여러 대가 데이터를 공유해야 하니 일관성 문제가 생기고, "다섯 대 중 한 대만 죽은" 부분 실패라는 새 장르의 장애가 생긴다. **분산 시스템 공부의 나머지 대부분은 사실상 수평 확장의 청구서다.**

**실무 감각**: 둘은 배타적이지 않다. 보통 애플리케이션 서버는 일찍 수평 확장하고, **DB는 최대한 수직 확장으로 버틴다**. DB를 수평으로 쪼개는 순간(샤딩) 난이도가 급상승하므로 "스케일업으로 버틸 수 있을 때까지 버틴다"가 흔한 전략.

| 기준 | 수직 확장 (Scale-up) | 수평 확장 (Scale-out) |
|---|---|---|
| 방법 | 더 좋은 기계 한 대 | 평범한 기계 여러 대 |
| 천장 | 있다 (최고 사양이 한계) | 사실상 없다 |
| 비용 | 스펙 올릴수록 가성비 급락 | 선형에 가까움 |
| 가용성 | SPOF — 죽으면 전부 죽음 | 한 대 죽어도 나머지가 받아줌 |
| 복잡도 | 코드 그대로 | LB·일관성·부분 실패의 청구서 |

## 무상태(Stateless) 서버: 수평 확장의 입장권

수평 확장의 전제: **어떤 요청이든 아무 서버나 처리할 수 있어야 한다.**

반례 - 서버가 자기 메모리에 세션을 저장하면:

![세션이 서버 안에 있을 때 vs 밖으로 뺐을 때](/assets/img/system-design-02-stateless-session.png)

서버가 상태를 품는 순간 그 사용자는 그 서버에 묶인다:

- LB가 같은 사용자를 같은 서버로 보내야 함(sticky session) → 부하가 고르게 안 퍼짐
- 서버 1이 죽으면 그 서버 세션 사용자 전원 로그아웃 → 서버 추가/제거가 무서워짐
- 배포하려고 서버 내릴 때마다 사용자가 튕김 → 롤링 배포가 어려워짐

**해법은 상태를 없애는 게 아니라 서버 밖으로 빼는 것:**

- 세션 → Redis 같은 공유 저장소, 또는 JWT처럼 클라이언트가 들고 다니게
- 업로드 파일 → 로컬 디스크가 아니라 오브젝트 스토리지(S3)
- 영속 데이터 → DB

서버는 "요청 받고 → 공유 저장소 읽고 → 응답하고 → 잊어버리는" 교체 가능한 부품이 된다. **오토스케일링 자체가 "서버는 무상태"라는 전제 위에서만 작동한다.**

이것도 트레이드오프 - 메모리에서 읽던 세션을 Redis까지 갔다 오니 요청마다 네트워크 왕복 하나 추가. "약간의 지연을 지불하고 확장 자유를 산다."

## 정리

수직 확장은 단순함을 주지만 천장과 단일 장애점이 있고, 수평 확장은 천장을 없애주지만 분산의 청구서를 내민다. 그리고 그 청구서를 감당하는 첫 준비물, 즉 **서버에서 상태를 빼내는 것**이 수평 확장의 입장권이다.
